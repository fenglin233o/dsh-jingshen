# 实现与验证记录

本包为 `dsh-jingshen` 0.4.5，唯一目标宿主为 DeepSeek Harness **0.2.2-rc.5**。当前验证范围为 Linux 本地 Web。0.2.0 在 rc.3 上的记录作为升级基线保留在 [0.2.0 验证档案](https://github.com/fenglin233o/dsh-jingshen/blob/v0.2.0/docs/verification.json)。

## SuperAgent 基底与改造范围

上游为 [`deepseek-ai/dsh-superagent-prototype`](https://github.com/deepseek-ai/dsh-superagent-prototype)，提交 `8c32a9dc5d72c033816c6a8110b37f40cf94fba4`。包内 `upstream/` 携带必要源码和资源，可独立构建，不依赖父目录仓库。`upstream/PROVENANCE.json` 列明文件、来源与三处兼容改动；没有挂载 GitHub、飞书监听器或上游团队管理界面。

| 部件 | 在本包中的作用 |
| --- | --- |
| 上游 Engine、Ticket、Mandate、Assignment | 持续事项、范围、授权和执行生命周期 |
| 上游 Store、Effects | SQLite 事务、提交后投递、可恢复执行队列 |

| `autonomy.ts`、`opportunity-turn.ts` | 持续意向、有来源的观察和再访、无指定问题的开放机会、过期投递与实际回合核对 |
| `continuity.ts` | 跨会话共享的现行做法、版本冲突、与原生回合关联的公开经历 |
| `delegation.ts` | 官方子代理的真实运行、来源、委派归属和授权撤回 |
| `control.ts`、`index.ts` | 本人控制、真实权限预设、原生工具注册、撤销与并发控制 |
| `self-change.ts` | 候选源码、检查点、真实命令验证、应用与回退 |
| `activation.ts`、`scripts/run.mjs` | 独立监督进程、明确的激活请求、加载回执与失败记录 |
| `mediation.ts` | 在原生流发布前作出表达决定，把已交付内容与原生消息编号关联 |
| `conversation.ts` | 主通讯记录、本人输入去重、跨会话发言、工作状态与社交表情 |
| `client.tsx`、`spirit-ui.tsx`、`fish.tsx` | 工作画幅入口、通讯窗、通话中的小肥鱼和原生聊天来源提示 |
| `voice-*.ts(x)`、`vision*.ts(x)` | 同一主会话中的可打断语音、连续本机视觉和本人明确授权的播放控制 |

保留上游任务引擎的机械可靠性，不把其状态机解释成精神发展的阶段。模型可直接工作、交谈、记忆和反思；结构化形态、检验与修订是可选的表达工具，不是每次完成工作必须通过的仪式。

## 运行中的区别与约束

**请求来源。** 本人请求只能来自当前回合实际的 `user/message`，并排除插件转达来源。自主发起明确记录 `self`、理由和当时持续授权。跨会话发言通过原生收件箱 API 标记为 `spirit`；不调用会冒充本人新输入的 prompt 接口。检索网页、文件和其他会话提供材料，不自动取得本人身份。

**会话与权限。** 模型和思考强度通过会话自己的选择接口持久化；不更改宿主全局默认值。敏感操作询问与完全访问真实对应宿主权限预设。权限、暂停、恢复的变化带有修订号；等待确认或异步操作期间失效的授权不能在稍后继续使用。选择器只显示「精神」，预设 ID 为 `dsh-jingshen`。历史预设 ID `dsh-spirit` 与 `dsh-personal-spirit` 都会接回同一原生会话并保存当前预设标识。主会话按其持久身份参加中介。其他会话按各自的预设及实际参与范围运行。

**经验与记忆。** 工作记忆可以主动形成，保留真实工具调用来源，默认不标为本人确认。本人可接纳、拒绝、纠正、遗忘；替换保留沿革。可选结构化检验要求判断与材料对应、修订说明旧内容的去向、尺度变化说明具体依据。这些结构不能证明语义正确，更不能替模型证明其发展具有哲学必然性。

**主动活动。** 未解决意向、实际观察和模型选择的再考虑条件提供机会。完全访问下，空闲的主会话还可以得到无指定问题的机会。默认相隔至少 15 分钟，可配置或关闭。模型可以保持安静，同一实例也可在其他精神会话修订当前做法。发送、收到、作出判断、完成事项分别记录；`jingshen_decide` 必须回应准确的机会与投递标识。重启不会把已经接收但尚未判断的后台输入自动再发一遍；明确重试会获得新的投递标识。持续意向可以跨任务继续，任务结束不会把以后需要考虑的事情丢在失效的执行会话里。

**自身改造。** 验证通过不等于文件已应用，文件已应用不等于运行版本已加载，版本已加载也不等于行为改善。候选和源目录摘要、检查点、检查命令实际退出结果、应用日志与激活回执分别保存。独立启动器只响应明确请求，并在关闭旧进程前、关闭后及新插件就绪时核对来源。源码操作与激活共用锁；启动失败不无限重启。每次候选保存独立恢复脚本，可在插件无法加载时使用。

**通话数据。** 浏览器通过同源宿主接口接入当前通话。只有该通话接收到的已交付正文可以触发朗读。默认合成请求向固定的 Breeze HTTPS 地址发送正文、模型、语言和可选的演绎提示，接收单声道 24 kHz、16 位 PCM。同一次通话中的同一条消息只会发起一次朗读，1,000 个 Unicode 码点以内的正文整体提交，更长的回复依次请求各段。专用凭据输入框通过 Harness 原生凭据服务保存 `BREEZE_API_KEY`。合成时由宿主解析该凭据，也支持同名启动环境变量。通话接口向浏览器返回配置状态、通话事件和音频，密钥不经通话接口返回。打断或挂断会取消播放和读取。Breeze 的生成历史与账户结算按其服务规则处理。标准包保留本机 Zipformer 识别，PrimeTTS 权重及其 WASM 运行时随可选资产包发布。[Breeze 流式合成接口](https://docs.breezeblue.ai/api-reference/text-to-speech/stream-text-to-speech)

**运行边界。** 原生文件、命令、网络工具继续执行宿主自己的检查；完全访问不会创造系统管理员或其他账户权限。应用层状态与记录也不能防范拥有同一文件写权限的主体恶意篡改。源码检查点只支持普通文件，不包含依赖目录和 Git 数据，应用是逐文件原子写入，不能当作整个目录的原子事务。恢复时不会自动覆盖后来出现的冲突改动，也不会按一个可能复用的 PID 擅自接管遗留锁。

## 验证方法

`npm run check` 运行严格 TypeScript 检查、Vitest 测试以及宿主 ESM / 浏览器 CJS 构建。测试使用实际 SQLite、上游 Engine/Store/Effects、本机 HTTP 服务、临时文件系统与实际子进程，覆盖持久化、请求来源、授权撤回、事务回滚、自身改造、激活及面板行为。

另有 `tests/runtime-smoke.mjs`，在隔离的 `DSH_HOME`、状态目录和安装副本里启动**官方 Harness 0.2.2-rc.5**，注册只用于测试的确定性本地模型适配器。它通过实际 agent 循环、原生工具执行器、确认机制和 shell 工具执行检查，不以直接调用插件函数代替宿主集成。可重现命令：

```sh
npm run build
npm install --prefix /绝对路径/临时运行环境 @deepseek-ai/dsh@0.2.2-rc.5
node tests/runtime-smoke.mjs --runtime /绝对路径/临时运行环境 --scratch /绝对路径/空测试目录
node tests/runtime-smoke.mjs --runtime /绝对路径/临时运行环境 --suite open-activity --scratch /绝对路径/开放机会测试目录
node tests/runtime-smoke.mjs --runtime /绝对路径/临时运行环境 --suite chat --scratch /绝对路径/通讯测试目录
node tests/runtime-smoke.mjs --runtime /绝对路径/临时运行环境 --suite mediation --scratch /绝对路径/中介测试目录
node tests/runtime-smoke.mjs --runtime /绝对路径/临时运行环境 --suite voice --scratch /绝对路径/语音打断测试目录
```

浏览器审批验收在安装了 Playwright 与 Chromium 的测试环境中运行 `--suite approval-ui`，使用 rc.5 自己的审批请求和实际按钮。连续视频验收通过单独的 [视觉脚本](../tests/vision-browser-smoke.mjs) 指定视频输入文件及浏览器测试环境。

其中对延迟持久化的竞争条件检查明确使用时间故障注入：先完成原生真实写入，再延迟一次完成通知，以验证随后到来的本人控制不会被旧回调覆盖。测试适配器只产生预设的协议消息，不访问模型服务、不消耗模型账号额度，也不代表真实模型的理解或判断。

## 验证结果

0.4.5 的构建、升级、电话与自主表达覆盖范围见[本版验收记录](verification.json)。

0.4.3 的 Breeze 接线使用受控的请求与音频流测试。测试范围包括凭据、发言投递、HTTP 错误和打断。另用发行版合成适配器和真实 Breeze API 完成 7 次中文合成，收到首个音频块耗时 0.354 至 0.921 秒。浏览器播放和打断在真实 rc.5 中用受控音频流验证。各版本的归档以记录内的版本标识为准。[当前验证记录](verification.json) · [发行包复核](../marketplace/RELEASE-VALIDATION.md) · [0.4.2 本机语音验证记录](verification-0.4.2.json)

0.4.1 的角色声线与通话档案见 [0.4.1 验证记录](verification-0.4.1.json)。下文所述的 0.4.0 行为基线，包括自动化测试、rc.5 宿主、真实旧状态升级和 Linux 本地 Web，见 [0.4.0 验证档案](verification-0.4.0.json)。基线的本机模型适配器产生确定的协议事件，并经过宿主组装请求、调用工具、处理授权、投递与压缩等实际路径。真实模型的长期自主学习、行为改善、Electron、Windows 和 macOS 需要各自的运行证据。

另一次短对话在本机以 llama.cpp 运行 Qwen2.5-1.5B-Instruct。模型用中文作答，再独立决定原样交付。测试适配器将四种表达决定的格式交给模型，本人发言、最终答复和主会话的原生消息编号可以相互核对。放宽格式的两次尝试分别返回了普通文本和多余字段，两份草稿都没有发出。这项实测说明具体小模型对复核格式的支持会影响消息能否送达。[模型版本](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF/tree/91cad51170dc346986eccefdc2dd33a9da36ead9)

受控测试用模型返回上下文过长的协议错误触发原生压缩，随后从宿主日志断言确实生成了摘要，下一次请求采用其他会话更新过的状态。该检查验证压缩后的接续，窗口的实际大小取决于模型与配置。

升级测试先用已发行的 0.2.0 与 rc.3 写下真实旧会话、权限和意向，再在同一个 profile 和状态目录运行待验证的包与 rc.5。另一条用例从 0.3.0 与 rc.5 的真实状态升级，并校验旧聊天、消息游标和重启后的接续。目标版本从待验证包的清单读取。Linux Web 验证使用 Chromium 打开原生入口，检查预设列表、主会话、权限、暂停和恢复，再以同一原生日志和 SQLite 状态核对。

```sh
node tests/upgrade-smoke.mjs --old-package /绝对路径/0.2.0源码 --old-runtime /绝对路径/rc3测试宿主 --new-runtime /绝对路径/rc5测试宿主 --scratch /绝对路径/升级测试目录
```

0.4 的表达与通讯验收还监听原生 `agent/assistant-stream`。在生成草稿、复核改写、明确选择沉默、继续下一次表达和中途撤权各阶段，将流中实际出现的文本与最终 `assistant/message`、SQLite 交付记录和浏览器渲染作对照。浏览器语音与视觉的测试条件和生成样音来源见 [通话与视觉](MEDIA.md)。

普通正文复核使用本会话的供应商、模型与思考强度。直接采纳、修订或未能完成都有记录。复核的草稿上限为 32,000 字符，请求超时为 90 秒；主动暂停可立即撤回本轮。在通讯窗能看到的内容以持久交付记录为准。
