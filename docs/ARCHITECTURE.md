# 精神：持续行动与可改变实现的区分

本页说明运行结构中必须分清的对象。哲学依据见 [PHENOMENOLOGY.md](PHENOMENOLOGY.md)，安装、配置和验证结果见 [README](../README.md) 与 [IMPLEMENTATION.md](IMPLEMENTATION.md)。工具的具体参数以当前 Harness 注册的定义为准。

## 模型输出如何抵达本人

主会话按其持久 ID 接入，继续使用原来的原生日志与工作目录。普通工作区列表只保留项目会话；升级时解除已有主会话在该列表中的成员关系。本人开的项目会话、工作会话与事务会话按其实际参与关系接入。本人给项目单独设置的原生沙箱与询问规则继续生效，加入精神也能保持这一设置。rc.5 的 `agent/pre-step` 核对原生回合、来源、有效授权和当下的意向。`llm/stream` 在宿主公布首个文字片段之前暂存这一轮的模型输出。模型可以用 `spirit_reply` 决定说、续说、等待或静默。只有普通正文时，插件把本轮问题、当前做法和公开草稿交给同一会话的模型作独立表达判断。模型可以接受、修订或暂缓。这个额外请求只接收一项表达决定，不能调用动作工具。撤权、取消或失败会阻止草稿交付。

决定和最终原生 `assistant/message` 配对后，才可以用会话与消息 ID 查到发布来源。主通讯窗读取这条公开投影；其他参与会话的原生回复按钮区域读取同一条凭据。另有 `spirit_say` 让精神在需要时从所在会话独立向主会话发言，保留该原生会话、回合和调用的来源。本人明确发声与后台自主发起按真实输入和授权检查。去重依据已提交的编号，浏览器重连依据持久游标追平。

原生子代理以自己的模型与名字执行委派。成员返回的文本保留成员来源；父会话采用或修改结果向本人发言时，再由父会话完成中介。运行中的任务、媒体实播与暂停决定状态动画，社交表情由精神在授权内自行选用。通话和视觉与文本共用同一主会话与运行控制。接口和参与边界见 [实现记录](IMPLEMENTATION.md) 和 [媒体说明](MEDIA.md)。

## 意向、尺度与权限

| 对象 | 作用 | 如何改变 |
| --- | --- | --- |
| 本人授权及运行控制 | 决定当前可执行范围、权限模式、暂停与停止 | 由本人控制入口改变；模型记录不能冒充本人选择 |
| 持续意向 | 保存准备关注或开展的事情及其根据 | 智能体可以形成、修订、完成或放下，本人也可纠正 |
| 认识与检验尺度 | 说明当前如何理解对象，什么材料支持这一理解 | 在实际经验中修订，并保留根据及此前内容 |
| 提示、代码和运行配置 | 实际影响模型接下来能做什么、如何工作 | 在已授权且可达的范围内修改，核实何时被运行环境采用 |

因此，自主发起工作不要求每次伪造一个新的本人请求，修订认识也不会自动授予新的操作权限。本人开启完整权限后，原本已获授权的行动可以直接推进；询问模式按实际权限机制处理需要询问的操作。应用控制与宿主、操作系统的实际能力共同决定边界，不能仅凭一段提示保证同权限进程无法修改本机状态。

## 一次机会可以没有行动

本人消息、被关注会话中本人的新消息、事务结果、主动设置的再访时间和运行恢复，都可能使智能体再次获得计算机会。当前 `watch` 关注本人消息，其他模型输出可按需要主动读取；它们不会全部自动触发新的唤醒。机会需要保存来源；后台结果和其他会话消息不能被标记成新的本人消息。

主会话结合当前意向、已有任务、记忆和材料，决定继续一件事、形成新事情、等待更多材料、重新安排再访，或不行动。`spirit_intent` 保存意向，`spirit_decide` 保存实际决定，`spirit_revisit` 安排以后再次考虑。定时条件不携带“必须每日自我改进”之类未由事情产生的目的。

主会话可以直接交流和行动。需要单独跟踪时，`spirit_start` 建立有来源的事项，`spirit_continue` 延续既有事项；执行会话保有本事项的历史和状态。创建多个会话是组织上下文与实际工作的手段，不代表分配固定人格、哲学阶段或企业岗位。

## 新会话与上下文压缩

同一实例在 SQLite 保存当前的行动取向、仍然有效的意向、所有者控制修订和投递状态。精神会话在宿主组装模型请求时取得有界的当前状态。主会话重连、换模型，或 Harness 因窗口耗尽压缩历史后，都走同一入口。窗口大小由实际模型与宿主决定。`spirit_orient` 带上读到的版本号和可公开说明的理由。两个会话同时改变同一判断时，后到且版本过旧的一方须依据当前版本重新判断。原生日志保存当时的对话、工具结果和结束原因，引用可以区分当时的表达和事后的解释。

`spirit_read(action=trace)` 按 `sessionId` 和回合起始序号 `startSeq` 读取公开发言、实际工具操作和结果。`spirit_decline` 可以登记对本轮本人请求的拒绝，同一条请求随后无法再作为派工依据。自主工作明确以某一版本的意向为依据时，可在发起或继续该工作时给出 `intentId` 与 `intentRevision`。撤销该意向会停止依赖旧版本的工作，其他独立事项继续。

完全访问、活动已恢复、主会话有可用模型且空闲时，时钟可以提供没有预设问题的机会。当前取向的 `attention` 可选择 `quiet`，已有具体事项仍按自己的条件处理。每次开放机会都核对运行状态与持续授权。本人开出的新精神会话和精神自己建立的会话在此状态中工作。受委派的原生子代理用其真实的会话来源送回结果，是否据此修订共同判断由接收会话决定。

开放回合可以没有回复。模型未登记判断且原生回合正常结束时，插件记录回合和结束序号，释放这次机会，下次仍可活动。显式拒绝、正常静默、回合中断在记录中可以区分。

团队模式属于宿主的根会话与子代理树。开启时共享任务板，关闭后任务和子代理仍然存在。任务完成、收到队友陈述、精神采纳其判断是三个可以分别观察的事实。工作树内的文件也是共享的，任务板的修订检查仅保护板上任务。宿主按创建关系和实际发送者提供消息与结果，暂停或撤回精神的活动须处理所属委派并保留无关团队的运行。[团队](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.5/packages/team/agent-team/README.zh.md) · [子代理](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.5/packages/subagent/subagent/README.zh.md)

## 行动与理解记录

宿主提供实际读写、命令执行及其他已配置工具；注册了一个工具名不保证对应服务、凭据或模型在当前机器上可用。`spirit_sessions` 提供会话与可用模型配置的相关操作。跨会话内容始终携带来源，其后产生的行动仍须处在有效授权内。

任务交付说明已经做成什么、证据在哪里、还有哪些限度。一个有界成果可以带有明确未解决的问题；这不允许把未兑现的承诺改名为已经完成。已有的 `spirit_frame`、`spirit_examine`、`spirit_revise` 用于需要精确描述理解变化时，不是所有工作的必经状态机。`spirit_evidence` 与 `spirit_memory` 分别保留重要材料和跨会话可用的经验。

记忆应区分本人表述、观察和推断，保留来源及可修订状态。日常工作记忆可以由智能体自行形成；模型认为某事成立，不等于本人曾确认它。新的判断影响以后的工作，旧记录仍用于说明过去为何如此行动。

## 自修改的几个不同结果

`spirit_change` 管理可比较、可验证、可回退的文件改变。候选文件由原生工具实际编辑，验证命令通过 Harness 的执行与权限机制运行。

| 记录或结果 | 能证明什么 | 还不能证明什么 |
| --- | --- | --- |
| 变更记录与旧版本快照 | 修改意向、根据及修改前的内容已保存 | 候选版本已经产生或有效 |
| 候选版本及比较结果 | 哪些具体文件内容发生了变化 | 程序可以构建、能运行或改善了行为 |
| 验证记录 | 被记录的命令对相应候选内容取得了哪些结果 | 未检查的行为成立，或后续编辑仍受这次验证覆盖 |
| 文件应用记录 | 候选内容已写入目标目录 | 当前进程已加载新版本 |
| 插件重载或宿主重启及其观察 | 新代码是否被运行环境采用 | 所有行为正确，或改变在哲学上必然有效 |
| 后续行为材料 | 实际观察到什么结果与困难 | 永久改善、意识成立或已经完成扬弃 |

文件应用本身不会把“运行已激活”标为成功。本人可以用安装包中的 `scripts/run.mjs` 启动指定 Harness profile 的监督进程；它只运行本人在命令行提供的可执行文件和参数，不从模型记录中读取新命令。模型明确请求加载已验证、已应用的版本后，监督进程核对源文件摘要，终止原来的子进程一次，再以相同命令启动新进程。插件完成初始化后提交启动回执，再次核对相应源文件，才记录 `runtime-loaded`。

激活与源码验证、应用及独立恢复共用 `self-changes/operation.lock`。已有操作尚未释放锁时，激活保持等待，原进程继续运行；监督进程获得锁后，持有到替换进程的启动结果明确。原进程退出后还要再次核对源码，退出钩子或外部写入造成的不一致会阻止新进程启动。原生工具或其他程序的任意文件写入未必参加这一锁协议，不能把它描述成对所有并发写入的文件系统隔离。

异常退出留下的操作锁不会根据保存的 PID 被自动移除。恢复前需停止参与操作的进程，检查并移除残留锁，再运行保存的恢复脚本；仅有“PID 看起来已经不存在”不足以安全地接管一个可能正在变化的锁。

没有相应监督进程时，激活请求记录为 `restart-required`，之后不会因监督进程出现就自动执行。需要一次新的明确请求。启动失败或超时会留下失败记录并停止，不进行无限重启，也不擅自决定回退源文件。变更记录中的 `recoveryScript` 保存在可变源码之外，可用于独立检查或回退；回退文件之后仍需启动或重启所需进程。

`runtime-loaded` 证明新的子进程中“精神”插件已就绪，不证明行为改善，也不表示每一个脚本都已执行。监督进程本身仍使用已加载的 JavaScript；改变监督脚本之后，需要本人重启监督进程才能采用。终止监督进程会终止它管理的子进程并禁止重新拉起。普通的精神活动暂停则取消尚未开始的激活；已经进入重启的操作会使 Harness 恢复运行，并继续遵守持久保存的活动状态。

验证、比较和回退使改变可检查、可恢复；它们不代替对改变根据的判断，也不强制每次唤醒都产生新版本。修订预算、命令期限、文件大小和上下文上限是有限机器的运行条件，应与哲学阶段分开。

## 停止与恢复

本人暂停或停止后，模型不能通过新意向、延后的机会或其他会话重新解释为已经恢复授权。单项事情的终止、全局活动状态与进程重启是不同状态，应按各自的持久记录处理。

运行中断时，已经发生的外部效果可能先于最终报告。恢复工作需要查看既有结果与历史，避免把同一操作重复当作尚未开始。源码回退及独立恢复入口帮助修复损坏的运行实现，但也不能证明外部发送、发布或其他已经发生的结果已被一并撤销。
