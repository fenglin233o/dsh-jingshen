# 实现与验证记录

本包为 `dsh-jingshen` 0.2.0，针对 DeepSeek Harness **0.2.2-rc.3**。验证环境为 Node.js 24.22.1、Linux；Windows 启动说明和 PowerShell 分支未在本次环境中实机验证。

## SuperAgent 基底与改造范围

上游为 [`deepseek-ai/dsh-superagent-prototype`](https://github.com/deepseek-ai/dsh-superagent-prototype)，提交 `8c32a9dc5d72c033816c6a8110b37f40cf94fba4`。包内 `upstream/` 携带必要源码和资源，可独立构建，不依赖父目录仓库。`upstream/PROVENANCE.json` 列明文件、来源与三处兼容改动；没有挂载 GitHub、飞书监听器或上游团队管理界面。

| 部件 | 在本包中的作用 |
| --- | --- |
| 上游 Engine、Ticket、Mandate、Assignment | 持续事项、范围、授权和执行生命周期 |
| 上游 Store、Effects | SQLite 事务、提交后投递、可恢复执行队列 |
| `service.ts`、`experience.ts` | 本人请求与自主发起的区别、经历、记忆、反思、具体事项的继续与结果 |
| `harness-bridge.ts` | rc.3 原生会话分页、带来源的消息投递、去重、模型与思考强度选择 |
| `autonomy.ts` | 持续意向、观察、一次性再考虑机会、显式判断回执 |
| `control.ts`、`index.ts` | 本人控制、真实权限预设、原生工具注册、撤销与并发控制 |
| `self-change.ts` | 候选源码、检查点、真实命令验证、应用与回退 |
| `activation.ts`、`scripts/run.mjs` | 独立监督进程、明确的激活请求、加载回执与失败记录 |
| `client.tsx`、`http.ts` | Harness 原生侧栏面板、控制、可查阅记录与导出 |

保留上游任务引擎的机械可靠性，不把其状态机解释成精神发展的阶段。模型可直接工作、交谈、记忆和反思；结构化形态、检验与修订是可选的表达工具，不是每次完成工作必须通过的仪式。

## 运行中的区别与约束

**请求来源。** 本人请求只能来自当前回合实际的 `user/message`，并排除插件转达来源。自主发起明确记录 `self`、理由和当时持续授权。跨会话发言通过原生收件箱 API 标记为 `spirit`；不调用会冒充本人新输入的 prompt 接口。检索网页、文件和其他会话提供材料，不自动取得本人身份。

**会话与权限。** 模型和思考强度通过会话自己的选择接口持久化；不更改宿主全局默认值。敏感操作询问与完全访问真实对应宿主权限预设。权限、暂停、恢复的变化带有修订号；等待确认或异步操作期间失效的授权不能在稍后继续使用。旧会话兼容保留 `dsh-personal-spirit` preset，主会话标识及默认状态目录保持稳定。rc.3 的工作区导航可能隐式重用空会话并覆盖预设；本包对原生公开 `create` 方法做了限定兼容：仅在重用已托管空会话且没有明确指定预设时保留其现有选择，明确选择与其他会话不变，卸载时撤回兼容处理。

**经验与记忆。** 工作记忆可以主动形成，保留真实工具调用来源，默认不标为本人确认。本人可接纳、拒绝、纠正、遗忘；替换保留沿革。可选结构化检验要求判断与材料对应、修订说明旧内容的去向、尺度变化说明具体依据。这些结构不能证明语义正确，更不能替模型证明其发展具有哲学必然性。

**主动活动。** 未解决意向、实际观察和模型选择的再考虑条件提供机会。时钟只交付已形成的机会，不规定每小时更新或预设发展的阶段。发送、收到、作出判断、完成事项分别记录；`spirit_decide` 必须回应准确的机会与投递标识。重启不会把已经接收但尚未判断的后台输入自动再发一遍；明确重试会获得新的投递标识。持续意向可以跨任务继续，任务结束不会把以后需要考虑的事情丢在失效的执行会话里。

**自身改造。** 验证通过不等于文件已应用，文件已应用不等于运行版本已加载，版本已加载也不等于行为改善。候选和源目录摘要、检查点、检查命令实际退出结果、应用日志与激活回执分别保存。独立启动器只响应明确请求，并在关闭旧进程前、关闭后及新插件就绪时核对来源。源码操作与激活共用锁；启动失败不无限重启。每次候选保存独立恢复脚本，可在插件无法加载时使用。

**运行边界。** 原生文件、命令、网络工具继续执行宿主自己的检查；完全访问不会创造系统管理员或其他账户权限。应用层状态与记录也不能防范拥有同一文件写权限的主体恶意篡改。源码检查点只支持普通文件，不包含依赖目录和 Git 数据，应用是逐文件原子写入，不能当作整个目录的原子事务。恢复时不会自动覆盖后来出现的冲突改动，也不会按一个可能复用的 PID 擅自接管遗留锁。

## 验证方法

`npm run check` 运行严格 TypeScript 检查、Vitest 测试以及宿主 ESM / 浏览器 CJS 构建。测试使用实际 SQLite、上游 Engine/Store/Effects、本机 HTTP 服务、临时文件系统与实际子进程，覆盖持久化、请求来源、授权撤回、事务回滚、自身改造、激活及面板行为。

另有 `tests/runtime-smoke.mjs`，在隔离的 `DSH_HOME`、状态目录和安装副本里启动**官方 Harness 0.2.2-rc.3**，注册只用于测试的确定性本地模型适配器。它通过实际 agent 循环、原生工具执行器、确认机制和 shell 工具执行检查，不以直接调用插件函数代替宿主集成。可重现命令：

```sh
npm run build
npm install --prefix /绝对路径/临时运行环境 @deepseek-ai/dsh@0.2.2-rc.3
node tests/runtime-smoke.mjs --runtime /绝对路径/临时运行环境 --scratch /绝对路径/空测试目录
```

其中对延迟持久化的竞争条件检查明确使用时间故障注入：先完成原生真实写入，再延迟一次完成通知，以验证随后到来的本人控制不会被旧回调覆盖。测试适配器只产生预设的协议消息，不访问模型服务、不消耗模型账号额度，也不代表真实模型的理解或判断。

## 本次交付的验证结果

下列为私用基底的验证记录；公开包更名后的复核结果另见 `marketplace/RELEASE-VALIDATION.md`：

- 严格 TypeScript 检查通过；130 项测试通过，零失败。包括 19 项桥接测试、16 项主动性测试、41 项经验与服务测试、19 项源码改造测试、10 项真实子进程激活测试、13 项控制与 HTTP 测试、12 项面板测试。
- 宿主 ESM 与原生面板 CJS 构建通过。将源码复制到开发仓库之外，重新 `npm ci` 后，类型检查通过；独立构建的两个 JavaScript 文件与交付构建逐字节相同。
- 官方 Harness **0.2.2-rc.3** 中的 18 项受控集成检查全部通过：实际工作区成员关系、原生工具与消息来源、会话模型及思考强度、确认拒绝、授权撤回、暂停与停止、重启持久性、主动机会与明确判断，以及经原生 shell 验证后的源码应用和回退。
- 集成检查包含两项延迟原生持久化完成通知的竞争条件回归，以及暂停后直接收到新消息的检查；后者没有启动测试模型适配器，没有执行工具，也没有在恢复时偷偷重放该消息。
- 实际 Chromium 检查通过侧栏进入、权限 full → ask、原生会话权限同步、暂停与恢复、键盘切换及手机布局；浏览器页面错误为零，390 像素视口下无面板横向溢出。未向实际模型服务发送消息。

机器可读摘要见 [verification.json](verification.json)。`tests/runtime-smoke.mjs` 会自行输出运行报告和原生日志证据；这份摘要记录所验证的构建摘要，便于确认安装包与测试对象一致。

没有使用本人的实际模型账号检验长期自主学习、复杂事务持续推进或改动后的能力改善。没有把确定性测试适配器说成真实模型推理，也没有把这些工程机制当作人工系统已经获得黑格尔意义上的精神的证明。《精神现象学》的参照、具体解释和限度另见 [原著对照](PHENOMENOLOGY.md)。
